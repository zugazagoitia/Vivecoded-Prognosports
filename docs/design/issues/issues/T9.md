**Referencia:** `docs/requisitos.md` §20.1, §20.2, §20.3

## Objetivo
Infraestructura de tests unitarios y de componentes, con mocks de la API v2 compartidos entre tests y desarrollo local.

## Alcance
- **Vitest** + `@vue/test-utils` + `happy-dom` (o `jsdom`), con el mismo `vite.config`.
- `@testing-library/vue` y `@testing-library/user-event` para tests de componentes centrados en el usuario.
- **MSW** (Mock Service Worker):
  - handlers en `src/mocks/handlers/<área>.ts` que devuelven el envelope `ApiResponse`;
  - fixtures tipadas con los tipos de T2 y validadas con los mismos esquemas Zod;
  - en tests: `setupServer`; en desarrollo: `setupWorker` con `VITE_API_MOCK=true` para trabajar sin la API real.
- Fixtures de una **temporada de referencia** (comunidad con 12 jugadores, 24 GP, 17 disputados, sesiones con y sin sprint) coherente con los ejemplos del mockup (`seed.js` es ficticio: se usa como inspiración, no como datos).
- Helpers: `renderWithProviders()` (Pinia, Query, i18n, router en memoria), `mockUser()`, `mockCommunity()`, reloj falso (`vi.useFakeTimers`) para cierres y cuentas atrás.
- **Cobertura** con `@vitest/coverage-v8`. Umbral obligatorio solo en lógica de pronósticos, validaciones, flags, guards y formateadores (§20.2): propuesta 90 % de líneas en `src/domain/**` y `src/utils/**`. Sin umbral en componentes visuales.
- Scripts: `test`, `test:watch`, `test:coverage`.

## Dependencias
T1, T2

## Criterios de aceptación
- [ ] `pnpm test` pasa con al menos un test de ejemplo por tipo (util, store, componente con MSW).
- [ ] `pnpm dev` con `VITE_API_MOCK=true` funciona sin red.
- [ ] Una fixture que no cumple su esquema Zod hace fallar los tests.
- [ ] `pnpm test:coverage` falla si la lógica de dominio baja del umbral.
