## Objetivo
Formulario de acceso con correo y contraseña. Si se llega desde una ruta protegida, avisa de que se volverá a ella tras entrar y redirige con `redirect`. Muestra un error claro si las credenciales no coinciden. En escritorio acompaña un panel visual con un mensaje sobre el próximo cierre de pronósticos. Cubre 2.1 y la parte de redirección de 1.6 y 2.8.

## Ruta y acceso
- Ruta: `/login` (query `redirect` opcional, ruta interna codificada).
- Requiere sesión: no. Con sesión iniciada, redirige a `redirect` o a `/home`.
- Rol: anónimo.
- Entradas: `redirect`; el guard `auth` añade `?redirect=` al expulsar (1.6).
- Salidas:
  - Éxito: si `User.verified` es falso → `/verify` (A5); si no → `redirect` (validado como ruta interna) o `/home` (H1); los guards `community`/`home` deciden después (sin comunidad → `/communities`, H2).
  - «¿Has olvidado tu contraseña?» → `/forgot-password` (A3).
  - «Regístrate» → `/register` (A2), conservando `redirect`.
  - Móvil: flecha atrás → `/` (P1).

## Secciones

### 1. Encabezado del formulario
- **Contenido:** h1 «Iniciar sesión»; «Entra para pronosticar con tu comunidad.» En móvil, encima, el logo de 48 px.
- **Estilo:** `h1.t-sub` (24/32 600), subtítulo `.t-sm.muted`, columna gap 4 (móvil gap 8).

### 2. Avisos
- **Contenido:**
  - Aviso de retorno `.alert.al-info` con icono info: escritorio «Inicia sesión para pronosticar el GP de Singapur. Volverás justo ahí.»; móvil «Inicia sesión para pronosticar el GP de Singapur.»
  - Error `.alert.al-err` con icono error y `role="alert"`: «**No hemos podido iniciar sesión.** El correo o la contraseña no coinciden.»
- **Lógica:** el aviso de retorno se muestra solo si hay `redirect` y no hay error (en el mockup, `back = !bad`). El texto depende del destino: si `redirect` es el pronóstico de un GP (G3), «Inicia sesión para pronosticar el {nombre del GP}. Volverás justo ahí.»; para otros destinos ⚠️ texto genérico no definido (propuesta: «Inicia sesión para continuar. Volverás justo ahí.»). El nombre del GP sale de `GET /v2/gps/{competition}/next` o del GP de la ruta (⚠️ a confirmar sin sesión). El error aparece tras un intento fallido (401/400 de `POST /v2/auth/login`) y sustituye al aviso de retorno; se oculta al volver a enviar.
- **Estilo:** `.alert` (gap 12, `padding:12px 16px`, radio 4, 14/20); info `var(--info-tint)`/`var(--info-fg)`; error `var(--err-tint)`/`var(--err-fg)`, la primera frase en negrita.

### 3. Campos
- **Contenido:**
  - «Correo electrónico»: icono sobre (mail), `type=email`, placeholder «tucorreo@ejemplo.com», `autocomplete="email"`.
  - «Contraseña»: en la misma fila que la etiqueta, a la derecha, enlace `.t-cap` «¿Has olvidado tu contraseña?»; icono candado (lock); `autocomplete="current-password"`; botón para mostrar u ocultar dentro del campo a la derecha (solo escritorio).
  - Casilla «Mantener la sesión iniciada en este dispositivo» (marcada por defecto en el mockup; solo escritorio).
- **Datos:** `POST /v2/auth/login` con correo y contraseña (⚠️ a confirmar en API nombres de campos y si admite nombre de usuario). Respuesta: token → se guarda (localStorage, 23.3) en el store de sesión (T4); después `GET /v2/user/me`.
- **Lógica:** validación en cliente con VeeValidate + Zod: correo obligatorio con formato válido y contraseña obligatoria (⚠️ textos de error por campo no definidos en el mockup). Mostrar/ocultar: estado local `show` (falso); icono ojo (visibility) con `aria-label` «Mostrar contraseña» y, al mostrar, ojo tachado (visibility_off) con «Ocultar contraseña»; cambia `type` entre `password` y `text`. «Mantener la sesión»: ⚠️ no hay parámetro en la API; propuesta: si se desmarca, guardar el token en `sessionStorage` en lugar de `localStorage`.
- **Estilo:** `.field` (etiqueta `.lbl` + control); `.iw .inp` con padding izquierdo 36 px; el campo de contraseña con `padding-right:44px` y el botón `.btn-ghost.btn-sm.btn-ic` absoluto a `right:4px` con icono 16 px. Casilla `.chk` con caja 18 px radio 4, marcada `var(--ring)` con check blanco. En móvil `.inp` sin icono, `min-height:48px`.

### 4. Acciones
- **Contenido:** botón primario grande a ancho completo «Iniciar sesión»; separador (línea, «o» en `.t-cap.muted`, línea); botón contorno a ancho completo con icono enviar (send) «Continuar con Telegram». Pie de tarjeta centrado: «¿No tienes cuenta? » + enlace en negrita «Regístrate».
- **Interacción:** Enter en cualquier campo envía. Mientras se envía, el botón queda deshabilitado con indicador de carga (F3) y los campos no editables. Éxito → navegación según «Salidas». Error de credenciales → alerta de error y foco en el campo de correo (o en la alerta). Otros errores (red, 5xx) → toast de error (T7).
- **«Continuar con Telegram»:** ⚠️ no hay endpoint de login con Telegram en la API v2 (solo vinculación autenticada, 3.5). Propuesta: no mostrar el botón ni el separador hasta confirmarlo.
- **Estilo:** `.btn-primary.btn-lg.btn-block` (48 px); `.btn-outline.btn-block`; separador fila gap 12 con `hr.hr` flexibles; pie `.card-f` con `justify-content:center`. Móvil: ambos botones con `min-height:48px`.

### 5. Panel lateral (solo escritorio)
- **Contenido:** sobretítulo «Temporada 2026» (`.up` en `#d7c3eb`); h2 «El Gran Premio de Singapur cierra pronósticos en menos de un día.» (30/38 600 `#fff`, balance); párrafo «Tus amigos ya han pronosticado. ¿Y tú?» (`#ebe1f5`).
- **Datos:** año de la temporada en curso y próximo GP (`GET /v2/seasons/current/{competition}`, `GET /v2/gps/{competition}/next`, ⚠️ a confirmar sin sesión). «en menos de un día» es un plazo relativo hasta el cierre (inicio de la primera sesión − 5 min).
- **Lógica:** ⚠️ el mockup no define textos para otros plazos ni para cuando no hay próximo GP; propuesta: plazo relativo con T5 («en {n} días», «en menos de un día») y, sin próximo GP, ocultar el h2. «Tus amigos ya han pronosticado» no se puede saber sin sesión: texto fijo de marketing (⚠️).
- **Estilo:** ver Layout; se oculta en ≤640 px.

## Criterios de aceptación
- [ ] Con credenciales válidas se guarda el token, se carga `/user/me` y se navega a `redirect` (solo rutas internas que empiezan por `/`) o a `/home`.
- [ ] Usuario no verificado → `/verify` tras entrar.
- [ ] Credenciales incorrectas → alerta de error con `role="alert"`; desaparece el aviso de retorno.
- [ ] El aviso de retorno solo aparece si hay `redirect`.
- [ ] El botón de ojo alterna `type` y el `aria-label` entre «Mostrar contraseña» y «Ocultar contraseña».
- [ ] Durante el envío el botón está deshabilitado y no se puede enviar dos veces.
- [ ] Un `redirect` externo (`https://…` o `//…`) se ignora y se va a `/home`.
- [ ] A 390 px se pinta la variante móvil (sin panel, sin casilla, sin ojo, campos de 48 px, flecha atrás a `/`).
- [ ] «Regístrate» conserva el `redirect` en la query.

## Tests

- `postLoginTarget(user, redirect)`: no verificado → `/verify`; verificado → redirect seguro.
- Esquema Zod de login: correo inválido falla; contraseña vacía falla.
- Mapeo de error de API 401 → mensaje «El correo o la contraseña no coinciden.»; error de red → toast.
- `returnNotice(redirect, gpName)` devuelve el texto con el nombre del GP o null sin redirect.
