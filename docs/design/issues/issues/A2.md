## Objetivo
Alta de cuenta con nombre de usuario, correo y contraseña, aceptando términos y privacidad. Valida el correo mientras se escribe y muestra un medidor de seguridad de la contraseña. En escritorio, un panel lateral explica qué pasa después (código de verificación, comunidad, primer pronóstico). Cubre 2.2 y lleva a la verificación (A5, 2.3).

## Ruta y acceso
- Ruta: `/register` (query `redirect` opcional, se conserva para después de verificar).
- Requiere sesión: no. Con sesión iniciada redirige a `/home`.
- Rol: anónimo.
- Entradas: `redirect` opcional.
- Salidas:
  - Éxito → `/verify` (A5).
  - «términos de uso» → `/terms` (P6); «política de privacidad» → `/privacy` (P6). Recomendado abrir en pestaña nueva para no perder el formulario (⚠️).
  - «Inicia sesión» → `/login` (A1), conservando `redirect`.

## Secciones

### 1. Encabezado
- **Contenido:** h1 «Crea tu cuenta»; «Gratis y en un minuto.»
- **Estilo:** `h1.t-sub`, `.t-sm.muted`, gap 4.

### 2. Nombre de usuario
- **Contenido:** etiqueta «Nombre de usuario»; icono arroba (alternate_email); `autocomplete="username"`; ayuda «Es el nombre que verán tus amigos. Entre 3 y 20 caracteres.» (valor de ejemplo «alex_ruiz»).
- **Lógica:** longitud 3–20 (Zod). ⚠️ caracteres permitidos y unicidad: los valida el backend; mostrar su mensaje bajo el campo (⚠️ texto de error no definido en el mockup).
- **Estilo:** `.help` 12/16 `var(--muted)`.

### 3. Correo electrónico
- **Contenido:** etiqueta «Correo electrónico»; icono sobre (mail); `type=email`; placeholder «tucorreo@ejemplo.com». Error: icono error 16 px + «Escribe un correo válido.»
- **Lógica (renderVals):** `inválido = valor.length > 0 && !/^\S+@\S+\.\S+$/.test(valor)`. Con valor inválido el campo lleva `.inp.bad` (borde y halo `var(--err)`) y aparece el texto de error `.errt`. Vacío no muestra error mientras se escribe (sí al enviar ⚠️ texto).
- **Interacción:** se valida en cada pulsación (estado local `email`).

### 4. Contraseña y medidor
- **Contenido:** etiqueta «Contraseña»; icono candado (lock); `type=password`; placeholder «Al menos 8 caracteres»; `autocomplete="new-password"`. Debajo, medidor de 4 segmentos y ayuda «Seguridad: **{nivel}**. Mezcla letras, números y símbolos.»
- **Lógica (renderVals):** puntuación `sc` de 0 a 4: +1 si longitud ≥ 8; +1 si hay minúscula y mayúscula; +1 si hay dígito; +1 si hay símbolo (`[^A-Za-z0-9]`) y longitud ≥ 10. Nivel: `['muy débil','débil','media','buena','fuerte'][sc]`. Color: `[var(--err), var(--err), var(--warn), var(--ok), var(--ok)][sc]`. El segmento i (1–4) se pinta con el color si `sc ≥ i`; si no, `var(--border)`. Requisito mínimo para enviar: 8 caracteres (⚠️ a confirmar reglas de backend).
- **Estilo:** `.meter` rejilla de 4 columnas gap 4; segmentos de 4 px, radio 2. Nivel en negrita `var(--h)`.

### 5. Aceptación de términos
- **Contenido:** casilla «Acepto los [términos de uso] y la [política de privacidad]» con dos enlaces a P6.
- **Lógica:** obligatoria para enviar (2.2). ⚠️ texto de error no definido; propuesta: no deshabilitar «Registrarse»; si se envía sin marcarla, mostrar el error bajo la casilla para que se entienda el motivo.
- **Estilo:** `.chk` con caja 18 px; marcada `var(--ring)`.

### 6. Envío y pie
- **Contenido:** botón primario grande a ancho completo «Registrarse». Pie centrado: «¿Ya tienes cuenta? » + «Inicia sesión» en negrita.
- **Datos:** `POST /v2/auth/register` con usuario, correo, contraseña (⚠️ a confirmar en API nombres de campos, si devuelve token e inicia sesión, y si envía el código de verificación automáticamente o hay que llamar a `POST /v2/auth/send-verify-email`).
- **Interacción:** en el mockup es un enlace a Verificar; en la app es `type=submit`. Envío con indicador de carga y botón deshabilitado. Éxito → guardar sesión si hay token y navegar a `/verify` con el correo. Errores de campo del backend (usuario o correo ya usados) → bajo el campo correspondiente; otros → toast (T7).

### 7. Panel «Qué pasa después» (solo escritorio)
- **Contenido:** sobretítulo «Qué pasa después» (`#d7c3eb`) y 3 pasos con número en círculo (`.av` con `background:rgba(255,255,255,.18); color:#fff`) y texto `#ebe1f5`:
  1. «Te enviamos un código de 6 caracteres para verificar tu correo.»
  2. «Creas una comunidad o te unes con un código de invitación.»
  3. «Pronosticas el próximo Gran Premio.»
- **Estilo:** filas alineadas arriba, gap 12.

## Estados
- Carga (envío): botón deshabilitado con spinner.
- Vacío: no aplica.
- Error de validación: correo inválido «Escribe un correo válido.»; resto ⚠️.
- Error de servidor: toast de T7 con el mensaje de la API.
- Sin permiso: con sesión redirige a `/home`.

## Accesibilidad
- `<label for>` en cada campo (`un`, `em2`, `pw2`).
- Ayudas y errores enlazados con `aria-describedby`; campo con error `aria-invalid="true"`; el texto de error con `role="alert"` o región `aria-live`.
- El medidor es `aria-hidden` (mockup) y el nivel se comunica con el texto «Seguridad: {nivel}»; anunciarlo con `aria-live="polite"`.
- La casilla es un checkbox real (Reka UI) con los enlaces dentro de la etiqueta accesibles por teclado.
- Foco al primer campo con error tras enviar.

## Tema claro/oscuro
Tokens: `--err`, `--warn`, `--ok`, `--border` (medidor), `--border-input`, `--surface-input`, `--ring`, `--muted`. Panel lateral fijo en ambos temas (degradado y foto, textos `#fff`, `#ebe1f5`, `#d7c3eb`, círculos `rgba(255,255,255,.18)`).

## Fuera de alcance

## Criterios de aceptación
- [ ] Escribir «alex@» marca el campo en rojo y muestra «Escribe un correo válido.»; vaciarlo quita el error.
- [ ] El medidor responde a la contraseña: «abc» → muy débil (0 segmentos); «abcdefgh» → débil (1, rojo); «Abcdefgh» → media (2, ámbar); «Abcdefg1» → buena (3, verde); «Singapur2026!» → fuerte (4, verde).
- [ ] No se puede enviar sin aceptar términos, con correo inválido, usuario fuera de 3–20 o contraseña de menos de 8.
- [ ] Con alta correcta se navega a `/verify` mostrando el correo introducido.
- [ ] Errores de backend de usuario o correo duplicado aparecen bajo su campo.
- [ ] A ≤640 px el panel lateral no se muestra y no hay scroll horizontal.

## Tests
- `passwordScore`: '' → 0; 'abcdefgh' → 1; 'Abcdefgh' → 2; 'Abcdefg1' → 3; 'Abcdefg1!' (9 caracteres) → 3; 'Abcdefgh1!' (10) → 4.
- `strengthLabel` y `strengthColor` para 0–4.
- `isEmailInvalid`: '' → false; 'a@b' → true; 'a@b.c' → false; 'a b@c.d' → true.
- Esquema Zod de registro: usuario de 2 y 21 caracteres falla; 3 y 20 pasa; términos falso falla.
