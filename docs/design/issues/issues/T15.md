## Objetivo
Detectar cambios de contrato de la API v2 antes de que rompan la app: comparar la especificación publicada con la versionada y probar rutas reales de solo lectura.

## Alcance
- **Diff de especificación** (§20.4): job programado (diario) y manual que descarga `https://api.prognosports.com/openapi`, lo compara con `api/openapi.json` (con `oasdiff` o similar) y, si cambia, abre una PR con el nuevo archivo y los tipos regenerados (T2) para revisarla. Cambios incompatibles marcados en el título.
- **Tests de rutas reales** (§20.9): suite separada (`pnpm test:contract`), solo `GET`, contra la API pública, con una temporada de referencia (competición, temporada y comunidad pública fijadas en config). Valida cada respuesta con los esquemas Zod de T2: `gps`, `gps/next`, `sessions`, `grid`, `results`, `circuits`, `seasons`, `communities` públicas, `points` y `resume` de la temporada de referencia.
- Sin credenciales en CI: solo endpoints públicos. Los que requieren sesión se cubren con MSW.
- Tolerancia a la red: reintentos y que un fallo de red no se confunda con un cambio de contrato.
- Las correcciones de §24.7 tienen un test específico que avisa si la API las corrige (p. ej. si aparece `standingsByHits`).
