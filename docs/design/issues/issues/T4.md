**Código:** T4 · **Tamaño:** M

**Referencia:** `docs/requisitos.md` §1.7, §4.10, §15.1, §19 (Estado de cliente / de servidor)

## Objetivo
Separar estado de cliente (Pinia) y estado de servidor (TanStack Query) con convenciones claras, para que cada pantalla pida datos con una query ya escrita y cacheada.

## Alcance
- **Pinia** (`src/stores/`):
  - `session`: token, usuario actual (`User` saneado), `isAdmin` (`rank.admin`), `login()`, `logout()`. Token en `localStorage` (§23.3, decisión vigente) con clave única; se lee al arrancar.
  - `community`: comunidad activa; persiste su id en `localStorage` y recuerda la última usada (§4.10). Cambiarla no navega: invalida las queries dependientes de comunidad para que la pantalla actual recargue (Navegación: «Si cambias de comunidad, la pantalla se queda donde estás y recarga sus datos»).
  - `theme`: `light | dark | system`; aplica la clase `dark` (y `data-theme`) en `<html>` y lo persiste (§15.1, ver F1).
  - `ui`: estado efímero global (p. ej. panel de flags en previews, T6).
- **TanStack Query** (`@tanstack/vue-query`):
  - `QueryClient` con `staleTime` por defecto razonable (p. ej. 60 s), `retry` 2 salvo 4xx, `refetchOnWindowFocus` activado.
  - Fábrica de claves (`src/queries/keys.ts`) por área: `['gps', competition, season]`, `['points', community, competition, season]`, etc. Todas las queries que dependen de comunidad incluyen su id en la clave.
  - Un composable por recurso (`useNextGrandPrix`, `useCommunityPoints`, `useSessionTipps`, `useUserResume`…), creado a medida que lo necesitan las pantallas; esta issue deja la infraestructura y los de sesión/usuario/comunidad.
  - Mutaciones con invalidación explícita (p. ej. guardar pronóstico invalida `['tipps', …]`).
  - Errores de query → T7 (toast o error de sección según el caso).
- Al hacer logout: `queryClient.clear()` y reset de stores.
- Devtools de Vue Query solo en desarrollo.

## Fuera de alcance
- Cada query concreta de pantalla (va en su issue). Toasts (T7).

## Dependencias
T1, T2

## Criterios de aceptación
- [ ] Recargar la página mantiene la sesión y la comunidad activa.
- [ ] Cambiar la comunidad activa recarga los datos de la pantalla actual sin cambiar de ruta.
- [ ] Dos componentes que piden el mismo recurso hacen una sola petición.
- [ ] Logout limpia caché y stores; volver atrás no muestra datos del usuario anterior.
- [ ] El tema elegido sobrevive a la recarga.

## Tests
- Store `community`: guarda y restaura el id; si la comunidad ya no está entre las del usuario, cae a la primera.
- Cambiar comunidad invalida claves con ese id y no las de otras áreas.
- `session.logout()` vacía token, usuario y caché.
- `retry` no reintenta 401/403/404.
