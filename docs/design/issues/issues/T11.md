## Objetivo
CI en GitHub Actions que compila una sola vez y prueba exactamente lo que se despliega, con permisos mínimos, acciones fijadas por SHA y escaneo de seguridad.

## Alcance
- **`ci.yml`** en `pull_request` y `push` a las ramas principales (§21.1):
  1. `install`: `pnpm install --frozen-lockfile` con caché de pnpm (§21.3).
  2. `lint` (T8), `typecheck` (`vue-tsc`), `test:coverage` (T9).
  3. `build` una vez por modo necesario (`beta`/`production`), sube `dist/` como artefacto (§21.2).
  4. `size` (presupuesto de bundle de T14) sobre ese `dist/`.
  5. `e2e` (T10) descargando el artefacto, con caché de navegadores de Playwright.
- `VITE_GIT_*` calculado con el SHA del commit y `fetch-depth` suficiente (§21.7).
- **Seguridad**:
  - `permissions` mínimos por job (`contents: read`; `pull-requests: write` solo en el que comenta la preview) y `persist-credentials: false` en `checkout` (§21.4).
  - Todas las acciones de terceros fijadas por SHA de commit con comentario de versión (§21.5).
  - `concurrency` por rama/PR con `cancel-in-progress` (§21.6).
  - PRs de forks: sin secretos y sin preview (§21.8).
- **`codeql.yml`** para JavaScript/TypeScript y `pnpm audit --prod` (falla en `high`/`critical`) (§21.13).
- **Dependabot** (`.github/dependabot.yml`) para npm y `github-actions`, semanal, agrupando menores y parches (§21.12).
- **Protección de ramas** (§21.10): documentar en el README qué checks son obligatorios para fusionar (lo configura el propietario del repo).
- Changelog con commits convencionales: opcional (§21.11), fuera de esta issue salvo que se decida.

## Dependencias

## Criterios de aceptación
- [ ] Una PR ejecuta lint, typecheck, unitarios, build, tamaño y E2E, y el E2E usa el `dist/` del job de build.
- [ ] Ninguna acción usa una etiqueta móvil (`@v4`): todas por SHA.
- [ ] Un push nuevo a la misma PR cancela la ejecución anterior.
- [ ] CodeQL y Dependabot están activos.
- [ ] Una PR desde un fork no tiene acceso a secretos.

- No aplica; se valida con una PR de prueba.
