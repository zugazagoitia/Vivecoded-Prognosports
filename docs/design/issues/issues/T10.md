## Objetivo
Tests de extremo a extremo en varios navegadores y en móvil, con accesibilidad automatizada y regresión visual en claro y oscuro, sobre el mismo `dist/` que se despliega.

## Alcance
- **Playwright** con proyectos `chromium`, `firefox`, `webkit` y `mobile` (viewport 390×844, `isMobile`, táctil).
- Servidor: `vite preview` sobre `dist/` ya construido (en CI se descarga el artefacto de T11). API mockeada con MSW o con `page.route` usando las mismas fixtures de T9; nunca la API real en E2E.
- **Flujos mínimos** (§20.5), que se completan a medida que llegan las pantallas:
  1. Login y registro (A1, A2), con `redirect`.
  2. Verificación de correo (A5).
  3. Crear comunidad o unirse con invitación (H4, H7).
  4. Hacer un pronóstico (G3): por clic, por teclado y en móvil con la hoja inferior.
  5. Ver resultados (G5) y ranking (R0, R1).
  6. Administración: listado de usuarios en solo lectura (M10) y 404 para no admin.
- **Accesibilidad** con `@axe-core/playwright` en cada página visitada: falla con violaciones `serious` o `critical` (§20.6).
- **Regresión visual** (§20.7) con `toHaveScreenshot` de componentes base (página de catálogo de F3) y páginas clave, en tema claro y oscuro, escritorio y móvil. Capturas solo en `chromium` para estabilidad; fuentes auto-hospedadas para que no varíen.
- **Core Web Vitals** (§20.8): medir LCP, CLS e INP en Inicio, Pronosticar y Clasificación con `web-vitals` inyectado; umbrales LCP < 2,5 s, CLS < 0,1, INP < 200 ms (en CI con red simulada).
- Trazas y vídeo solo en fallo; informe HTML como artefacto.

## Dependencias
T1, T9

## Criterios de aceptación
- [ ] `pnpm e2e` ejecuta los cuatro proyectos en local.
- [ ] Un botón de icono sin nombre accesible hace fallar el test de axe.
- [ ] Un cambio visual no intencionado en un componente base hace fallar la regresión visual.
- [ ] Los flujos se ejecutan contra `dist/`, no contra el servidor de desarrollo.
